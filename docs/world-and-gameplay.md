# World and Gameplay

World owns numeric content, chunks, generation, simulation utilities, CPU meshing and storage; the authoritative Server owns gameplay, time and persistence sequencing. Integrated and dedicated sessions use the same runtime. Client replicas neither generate nor save. Public interfaces: `include/maage/{world,generation,world_store,entities,random_ticks,crafting,containers,block_entity}.h`.

## Generation and Streaming

The Base module registers terrain, ore, feature, spawn and biome policies through public interfaces. Current biome categories are ocean, hills, taiga, desert, forest and plains. Regional sites use a seeded 128-block lattice with bounded jitter, climate/relief fields, local 3x3 classification support and distance-based edge blending. Materials remain categorical at the surface; relief can inherit neighboring climate for ecology. The generator is independent, without Java seed parity or a guarantee that every component has a minimum size.

Generation stages operate on detached columns, using immutable definitions and coordinate-derived randomness. Ore/feature callbacks execute at stable stage boundaries; worker completion order never changes feature ownership. Live saplings reuse the tree feature emitter. Square-ring World scheduling prioritizes near-player and forward missing terrain without waiting for previous rings. Disk loads/durable saves use a different worker pool from CPU generation, light and meshing. Short owner handoffs and revisions reject obsolete completions; unavailable collision columns remain obstructed.

A 16³ section holds numeric states. Published snapshots use adaptive uniform/palette-packed representations; private block mutations detach affected sections and lighting has separate reference-counted storage. These are memory representations, not content-ID ceilings. Borrowed immutable snapshots and registries outlive their jobs. The current algorithms are in `src/world/` and `src/base/generation*.c`.

## Persistence and Identity

Worlds reside under `instances/<uuid>/worlds/<uuid>/`. Current formats: `MGWRLD16` metadata with one checksummed `MGIDMAP3` identity dictionary, `MGRGN2` region files and `MGCHNK11` chunk records. The dictionary maps saved numeric block/state/item/item-variant/biome/entity-type IDs to current finalized definitions at open; saved states reference block identity plus canonical typed property assignments. Block/item constants are recorded once with their identity; variant records translate local item variants through canonical typed assignments. Property and identity-value names resolve only when opening the dictionary. Persisted chunk/region records contain numeric IDs only, compression/checksums and registered block-entity codecs selected by owning saved block identity. Missing, malformed or duplicate identities fail explicitly.

Owner edits create immutable save snapshots; async region writers clear dirty state only when the saved revision remains current. Metadata checkpoints player/inventory, weather/environment, RNG and retained active/dormant entities after a successful World flush. Living checkpoints include body/look orientation, health, variants, invulnerability, accepted hurt occurrences, death progress, goals, damage attribution and effect cursors; optional module state uses exact-size versioned word/stack codecs. Drop, behavior and spawn RNG streams and the rotating simulation cursor continue across saves. No open temporary GUI results or pointers are stored. Older development formats have no migration or automatic deletion. Details: `include/maage/world_store.h`, `src/world/{store,region_store}.c`.

## Random Ticks and Growth

At 20 TPS the unpaused owner retries pending neighbor work, services explicitly scheduled fluid/content updates, runs random ticks and ticks block entities. Available neighbor cascades drain before the phase publishes its edits. `maage_world_config_init` defaults `random_tick_speed` to 3; explicit zero disables it. Simulation distance defaults to radius 8 independently of Client render distance. Only loaded sections with eligible numeric states participate; per-section counts avoid repeated whole-block scans. Coordinate, behavior and weather RNG streams persist separately. Unavailable terrain/light defers mutations without synchronous loads or relighting.

Registered random behaviors include grass, saplings, leaves, farmland/wheat, cactus, mushrooms, snow layers and ice. Sapling stage/species and eight wheat stages persist as explicit typed property configurations. Minecraft crop, farmland, soil-plant, mushroom and cactus contracts share their applicable support/growth implementations with compatible registered content; specialized drops and tree generation remain module policy. Leaf-support classification queries the module-registered log/leaves tags, allowing compatible dependent content to participate. Sapling growth preflights a complete detached tree plan across required columns before commit. Natural leaves propagate connected-log support for at most four face-adjacent leaf steps; their check flags survive missing neighbors. Player-placed leaves persist. Existing built-in farming covers wheat, not other crops or bone meal.

## Block Changes and Directional Support

Every successful expected-state mutation reserves an exact before/after transition before changing its cell. No-op replacements create no work. Gameplay notifications are independent of geometry grouping, mesh invalidation and light epochs. The authoritative owner dispatches `CHANGED`, checks the destination's current support, then visits six adjacent receivers in -X, +X, -Y, +Y, -Z, +Z order. `NEIGHBOR_CHANGED` carries the changed position, receiving face, previous/replacement states and mutation origin; the receiving subject is its current state. Origins distinguish direct mutation, random/scheduled ticks, plans and resulting neighbor/support cascades. Client replica imports and detached generation never dispatch gameplay.

Callbacks append transitions rather than recursively entering dispatch. Columns rotate after each transition; each column preserves transition order and completed delivery bits. `neighbor_update_budget` defaults to 8192 deliveries per drain; yielding preserves both the record and the next delivery position, without limiting queue capacity. Owner ticks resume ready work fairly. Missing columns or predicate inputs leave the relevant delivery pending without loading terrain. Unavailable-only retries change owner cursors without cloning or dirtying snapshots. Deferred neighbor providers must report deferral before producing effects; dispatch preserves completed provider cursors while the receiving state remains unchanged.

The exclusive `SURVIVES` provider supplies a state-aware `maage_block_support_rule`: a six-face mask, ALL/ANY combination, immutable context and content predicate. The engine samples those neighbors and evaluates the registered predicate; a known decisive ALL failure or ANY success does not need unavailable alternatives. `SUPPORT_LOST` owns the outcome. `CAN_PLACE` is a separate read-only destination contract; plants may explicitly reuse ongoing survival, while falling-block placement permits unsupported destinations. Arbitrary content modules use the same Traits providers and numeric interfaces.

Minecraft content defines ground-supported plants, state-selected torch attachments, cactus ground/side requirements, farmland's upper-face condition, light-sensitive crops/mushrooms and falling-block support. It owns environmental drops, snow removal, farmland replacement and the handoff to existing falling entities. Ordinary support reactions occur in the initiating authoritative tick; they never enter the delayed scheduler. Random ticks perform registered growth/environment behavior without incidental structural checks. Loading, generation and random sampling do not activate untouched floating sand/gravel. Placing an unsupported falling block or removing its lower support initiates the ordinary iterative cascade.

Pending transitions, remaining faces, origins, numeric saved state references and provider cursors belong to the source column's immutable auxiliary snapshot and current `MGCHNK11` record. They survive saves, eviction/reload and asynchronous light replacement alongside independent scheduled queues and block entities. Once source and required neighboring terrain are resident, owner ticks retry them; loading itself adds no synthetic support checks. Region payloads are bounded by their actual unsigned 32-bit encoding and address space rather than a fixed pending-event ceiling. Incompatible previous World/chunk formats fail explicitly and require a newly created development world; existing files are preserved.

`maage_world_begin_mutations` / `maage_world_end_mutations` reuse the owner edit batch for code borrowing mutable simulation storage. The outer end drains notifications after those borrows finish. Falling entity creation and the item/falling physics walk use these scopes, so cascades cannot invalidate an active entity pointer or reserve the same instance identity twice. Detached tree plans publish all cells before dispatching their queued transitions. Scopes must finish before job polling or persistence.

## Entities and Item Drops

World owns growable typed entities with monotonic instance IDs distinct from content IDs. Item/falling records coexist with dynamically registered living/projectile types in the same store. Type definitions are immutable Content registrations; instance IDs, optional module state and active/dormant ownership are separate. The Server owns swept collision, pickup, active age and delay; entities freeze when required terrain is unavailable. Dormant and active entities belong to the World checkpoint rather than per-column files.

Mining reserves capacity for every drop before expected-state removal/tool wear/RNG changes. Drops become World item entities, never instant inventory grants. Q, Control-Q and cursor drops follow the same owner path. Pickup fills existing compatible stacks, keeps residual quantities in their entities and publishes copy-only cues. The Client's 0.15-second pickup interpolation is decorative; there is no gameplay magnet. Sand/gravel transfer into owned falling-block entities and either place saved state at landing or convert to item ownership without duplicating quantities. See `include/maage/entities.h` and `src/world/entities.c`.

## Living Entities and Natural Spawning

Content registers pig, cow, sheep, chicken, zombie, skeleton, creeper, spider and arrow definitions with copied dimensions, attributes, loot, sounds, models and spawn rules. New authoritative Worlds derive independent drop/behavior/spawn RNG streams from their seed; existing checkpoints restore their saved states. Server owner callbacks compose wandering/panic, obstacle steering/jumping, pursuit/line of sight, melee, ranged shots and retained explosions. Shared swept bodies handle gravity, fluids and environmental damage. Sheep own colored fleece/shearing/grazing state, chickens own egg timers and slow falling, and cows exchange buckets for milk. Creative catalogs expose eight registered spawn eggs; Server ray/reach and selected-stack validation remain authoritative.

`maage_entity_policy` configures rotating tick work, spawn attempts/intervals, class populations and player distances through World/Server creation. Finalization indexes weighted rules by numeric biome/classification; owner attempts inspect already loaded terrain, light, time, surface, fluid and collision without loading chunks. Base passive rules select grass in plains/forest/taiga/hills with light9–15; hostile rules use light0–7. Death publication retains pending transformed stacks and cursors when capacity fails; custom flat state and incremental effects checkpoint with the same World metadata. XP currently credits an attributed player directly; XP orb entities are not implemented.

Living entities publish accepted damage sequences independently of invulnerability. Ordinary rejected hits produce no new hurt cue or knockback; a stronger hit during resistance applies only its additional damage. Death stops AI and interactions, retains the body for 20 active owner steps, and removes it only after retained loot and XP processing completes. Both death progress and pending drop ownership survive checkpoints. Player actions and Client prediction share numeric ray/AABB selection with a 0.1-block border and block/unavailable-terrain occlusion. Entity targeting clears mining progress; preview acknowledgment still requires an actual newer owner mutation associated with its input sequence.

Navigation is local obstacle steering rather than a global route planner. Breeding, riding, milk consumption/status effects, complete mob-specific parity and remote entity wire encoding remain future work. Source implementation has not established gameplay, visual or performance correctness.

## Crafting and Furnaces

One finalized growable recipe registry serves temporary 2x2 inventory and 3x3 table grids. Shaped patterns offset/mirror but do not rotate; shapeless ingredients occupy distinct cells. Item variants are exact unless wildcarded; domain-aware item tags and typed property constraints also match ingredients. Property projections compile a unique output per eligible source variant during finalization. Shaped wins over shapeless, then occupied count and registration order. Matching allocates nothing. The Server validates numeric container identity, access/range, slot policy and result revision before preflighting all inputs, outputs and remainders. Bounded shift-click repetition does not permit infinite crafting loops.

Crafting Table storage is temporary: close returns cursor/inputs to inventory and reserves item entities for overflow. Failed closure retains unreturned stacks for retry/checkpoint; the open table and derived result are not saved. Furnaces instead use persistent World-owned block entities, registered codecs and containers. Separate numeric smelting/fuel registries drive 200-step owner cooking, snapshot progress and extraction-only fractional XP. GUI progress draws integer steps from authoritative copies, not Client timers. See `include/maage/{crafting,smelting,furnace,containers,block_entity}.h`.

Regular and trapped chests register persistent 27-slot block entities. Exactly two adjacent chests of the same registered block type compose a 54-slot container; placement rejects triples and adjacency to an existing pair. Different chest types remain independent. Owner block-entity ticks reconcile the shared facing against the pair axis and opaque front/back neighbors through ordinary expected-state replacements, preserving both inventories and the survivor's facing. Access validates loaded halves, original block identities, the eight-block range and clear space above both halves. Owner transactions validate both inventories before copying either, while close returns only the carried cursor. Breaking either half drops only that half's stored items and closes the former combined view; the surviving inventory retains ownership. Open viewers and lid phase are transient; item stacks and revisions use the registered codec. Trapped-chest redstone output awaits the redstone system.

## Creative Inventory Transactions

Use input names the published player snapshot used by Client placement prediction. The Server retains eight published owner poses and accepts an aim anchor only within four owner ticks and the same player life. It raycasts that pose against current authoritative terrain, while placement overlap, inventory and mutations use current authority. Expired anchors defer use rather than placing at a different newly sampled target; preview packets remain acknowledgements only.


Session protocol 27 carries typed catalog/player-slot, clone, hotbar, drop, destroy and clear actions. The Server validates Creative mode, health, the accessible personal container's identity and exact revision, registered tab/entry scope, item/variant/damage/count validity and slot/action bounds. Relative operations run in owner FIFO order; stale commands fail explicitly. Generic personal slot commands cannot bypass Creative policy.

Catalog selection owns no storage. Shared `maage_inventory_operate` transactions preflight player-slot changes in a copied inventory before commit, including distribution, collection, hotbar swaps and bounded transfers. Cursor and selected-slot ownership remain in the existing inventory/checkpoint. Deletion creates no entities; drops reserve World entity capacity before ownership changes. Creative closure drops its carried stack before normal container teardown, retaining it and retrying when reservation fails. Survival crafting/table/furnace closure and persistent block-entity ownership use their existing paths.

## Current Limits

MaaGE has an initial registered passive/hostile mob roster and local behavior system; richer AI/navigation, complete combat/Survival, redstone, dimensions and remote multiplayer remain future work. Neither generator nor presentation promises exact Minecraft 1.7.10 parity. See [the roadmap](development-roadmap.md) for plans and [AGENTS.md](../AGENTS.md) for durable rules.
